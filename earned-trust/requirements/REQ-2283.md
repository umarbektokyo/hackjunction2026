# REQ-2283 — Generator and analyzer crash on a closed generic struct from a referenced assembly

Source: https://github.com/MessagePack-CSharp/MessagePack-CSharp/issues/2283 (bug)

## Intent
The source generator and analyzer must not crash when a `[MessagePackObject]` type has a member
whose type is a closed generic value type (e.g. `Item<int>`, `record struct Item<T>`) defined in a
referenced assembly. Today both throw `IndexOutOfRangeException` (CS8785 / AD0001), the generator
stops producing output, and the assembly silently ships without a generated resolver (NativeAOT and
trimmed apps then fail at run time).

## Functional requirements
- F1. Building a project that references a generic value type with `[MessagePackObject]` from another assembly completes without CS8785/AD0001.
- F2. The generated resolver for the consuming project is still produced in that situation.
- F3. The trigger matrix from the report is covered: generic + value type + referenced assembly crashes; non-generic structs and generic classes already work and must keep working.
- F4. Existing diagnostics for types declared in the compilation being analysed keep their current locations and keep being reported.

## Non-functional requirements
- N1. No behaviour change for types declared in source (regression tests must still pass).
- N2. The fix is in the analyzer/generator (`MessagePack.SourceGenerator`), not a workaround in user code.
- N3. The change is small and reviewable; no unrelated dependency or build changes.

## Root cause (from the report)
`TypeCollector.GetObjectInfo` indexes `DeclaringSyntaxReferences[0]` in several diagnostic paths; that
collection is empty for metadata symbols. Neighbouring helpers already use `FirstOrDefault()`.
