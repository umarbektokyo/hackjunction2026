# REQ-2129 — Allow generation of a formatter for a type in a referenced assembly

Source: https://github.com/MessagePack-CSharp/MessagePack-CSharp/issues/2129 (feature)

## Intent
Project A is a dependency-free library defining `MyType`. Project B references A and MessagePack.
Users want the source generator in Project B to emit an `IMessagePackFormatter<MyType>` for a type
it does not own, instead of hand-maintaining a copied formatter.

## Functional requirements (maintainer-agreed design)
- F1. A new attribute, e.g. `[GeneratedMessagePackFormatter(typeof(External))]`, on a partial class implementing `IMessagePackFormatter<T>` makes the generator fill in the implementation.
- F2. Keys for the external type's members come from a **surrogate type** carrying the MessagePack attributes (`SurrogateType = typeof(...)`), matched to the external type's properties by name; or, when no surrogate is given, from contractless (property-name) mode. The surrogate is generator input only and is not used at run time.
- F3. Analyzers flag a surrogate property that has no matching property on the external type, and a missing key on the surrogate.
- F4. Copying MessagePack attribute definitions into Project A is explicitly rejected (reflection resolvers would not recognise duplicates).
- F5. The generated formatter is registered in the project's generated resolver like any other formatter.

## Non-functional requirements
- N1. Only public members are serialized (confirmed with the requester).
- N2. Existing generation output for owned types is unchanged (snapshot tests pass).
- N3. Documentation for the new attribute and new analyzer IDs.
